### Recommendation

Resolve this through semantic colour roles, not per-design token overrides.

1. Move every per-design colour decision out of the `planner.css` body-class rules into the design's palette in `designs.LOOK_PALETTES` (so `config.resolve_palette` sees it; the 02, 06, 11 and 12 entries already hold most of these values). Chrome that needs more than the twelve tokens (the `--lx-*` frame set, Beautiful day's `#C46A78` title, Executive desk's `#7A8798` slate) becomes named roles computed in `colours.roles` beside `structure`, `weekend` and the seasons, with per-design picks in `colours.PICKS` (a token name, so a `palette:` block still reaches it, or a hex).
2. CSS then reads only `:root` tokens and `--c-*` roles, never a literal. The `--lx-*` set at `planner.css:2103` and `2177` already does this for the neutral default; the four overrides at `2114-2117` go.
3. A test that no CSS rule outside `:root` defines a palette token or a `--c-*` role, and that no design-scoped rule (`.design-*`, `.box-*`, `.d02-` to `.d12-`, `.lk*`) uses a raw hex for chrome. The scan in the audit above is the shape of it.
4. Order of work: the offered layouts `02`, `06`, `11`, `12` first (`.design-02` first, since it is all one colour); the retired looks last or never.

## Colour rule, 2026-10-12 (branch `colour-system`)

Carla said the colours inside the worksheets were haphazard: in a layout like `06b` the Family Time header cells went navy, red, navy, red; the day pills alternated; card tabs differed; the annual calendar's month bars ran red, red, navy, navy, red, red, blue and so on, with matching borders. **Carla approved this colour rule on 2026-10-12.** It now holds on every page of all 27 designs (13 looks, 12 layouts, blank, original). The rule is in `_config/design-system.md` ("Colour roles"); the code is `familyplanner/colours.py`, wired in by `render.colour_roles` and `render.month_key`.

1. **Structure**: one colour per design (its title colour, palette `navy`) for every table header, card tab or heading, section label, banner, badge and numbered circle. No alternating colour lists are left in the templates (`[...][loop.index0 % n]`, per-day lists, per-row chips), and the nth-child colour cycles in the CSS that the 27 designs use are gone (Executive desk's every-other tab, the `06b` tape colours, the `12a`/`12b` card tones; each now has one). Cycles are left only in the CSS of the retired looks `13`, `14` and `16`, which are not offered and which no layout builds on.
2. **Weekend**: one accent per design (palette `red`, darkened only where text needs it) for Saturday and Sunday labels, pills, weekend columns and dates everywhere: worksheets, the month grids of every look and layout, the weekly and daily sheets, the annual calendar. Weekdays are the structure colour. The accent is used for nothing else on a worksheet; totals sit on a light wash of the structure colour. Exceptions, written down in `colours.PICKS`: Almanac's red is almost its oxblood title colour, so its weekend is its ochre (`orange`); Boxed records has no colour, so its weekend is a mid grey; Executive desk's red is a slate next to its navy, so its weekend is a muted brick. The weekend is darkened to 5.3:1 on paper, so it reads 4.5:1 or better on light cells and washes too. Farmhouse prints its titles and month names in the same barn red as its weekend (titles were left alone).
3. **Seasons**: winter (Dec, Jan, Feb), spring (Mar to May), summer (Jun to Aug), autumn (Sep to Nov), four colours from each design's own palette, hand-picked per look, layout family and theme in `colours.PICKS` (tints or shades of the palette where it has too few colours; an algorithm only for a custom palette). Used on the annual calendar's month boxes, the contents and tab-rail month entries, and the month accents that exist (the Editorial and Swiss month numbers; Blank and original's script line and month art). A month's `accent` is now `season` by default; a palette name still works for Blank and the retired looks. Text on every role colour is white or the ink at 4.5:1 or better.
4. Neutral fills stay. The budget donut keeps its category colours (a chart). Covers, page titles, fonts, textures and cover art are unchanged.

## What this is

Family Success Planner is an ICM factory (`CLAUDE.md` → `CONTEXT.md` → stage `CONTEXT.md`) for printable planner books, plus a local Python app (`planner.py`, `familyplanner/`) that renders them. The repo may be made public, so it must never carry a real family's name (see Locked decisions).

## Where everything lives

- Repo root: the `family-planner-generator` folder on the owner's computer (the only clone; see Environment notes)
- Remote: `git@github.com:smiln32/family-planner-generator.git` (SSH; see Environment notes)
- Layer 0/1: `CLAUDE.md`, `CONTEXT.md`

## Locked decisions

- No real family names in the repo: not in docs, examples, tests, commit messages or run outputs. Use blank or made-up names (the code uses "Ramirez"). Personalisation happens in `family.yaml` or the UI, never by committing a run.
- The original illustrated house cover (`design: original`) is retired by the owner (2026-09-30), not restyled. It stays buildable as a legacy id so the printed run rebuilds as printed; do not restyle it and present it as a new look.
- The thirteen looks are owner-approved designs. Apply them as given; do not redesign, restyle or "improve" them. Looks `02`–`17` are legacy and unfinished. Do not invent cover art, florals or notebook chrome in chat without a human-approved reference image or written layout (see "Looks" above).
- Every value from YAML, CLI flags or the UI goes through the validators in `config.py`. New fields get a `check_*` helper and a test; nothing reaches a template or a file path unchecked.
- The local server answers only its own page. Keep all UI calls on the JSON `api()` helper in `ui.js`; a plain form post or `text/plain` fetch will get a 403.
- ICM rules from the conventions: references point one way (stages point to `_config/`, `shared/` and earlier stages' `output/`, never forward); one canonical home per fact; CONTEXT.md files route and stay under 80 lines; no em dashes; no spaces in file names.
- `out/` and root `family.yaml` are gitignored local scratch. A run's settings live only in `stages/02-customize/output/`; do not copy them to a root `family.yaml`. With no root file, `start-planner.bat` and plain `planner.py ui` open a blank planner; open a run with **Open a plan** or `planner.py ui -c <stage 02 yaml>`.
- One stage, one job; no coordinator script; reorder stages by renaming the numbered folders only.

## Environment notes

- Windows Smart App Control blocks Git for Windows' unsigned `libcurl-4.dll`, so HTTPS push and fetch fail or hang. This repo pushes over SSH with `core.sshCommand = C:/Windows/System32/OpenSSH/ssh.exe`. Do not switch the remote back to HTTPS.
- The owner runs pushes, opens pull requests and merges them. A local `carla-safety` hook blocks the agent from merging a pull request even when asked (it also trips on commands that merely contain the pull-request command text). Give one command at a time and wait for "done". Multi-line pull-request commands with a long body break when pasted into PowerShell: give a one-line command or the GitHub compare link (`.../compare/main...<branch>?expand=1`). After a push, confirm the remote matches with `git rev-parse` and watch CI (`gh run watch`) before saying a pull request is safe to merge. Last push (2026-10-03, `git push origin main`) was run by the agent because the owner asked for it in that message; it worked over SSH from the repo root.
- Any clone made before 2026-09-24 has the old history. Delete it and re-clone; never push from it, or the names and source pack return.
- The original source pack (reference planner PDF and 31 page JPGs) lives outside the repo at `..\planner-source-pack\`. Do not copy it back in; it must not be published.
- `git-filter-repo` is installed (`python -m git_filter_repo`) if history ever needs scrubbing again.
